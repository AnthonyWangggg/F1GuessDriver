# 开发验证

| 命令                         | 用途                                                 |
| ---------------------------- | ---------------------------------------------------- |
| `pnpm verify:quick`          | 日常改动；格式、相关代码检查与单测                   |
| `pnpm verify:standard`       | 功能阶段；按范围加入构建、数据库或页面测试           |
| `pnpm verify:full --dry-run` | 无执行副作用地列出完整验收计划，全部为 NOT_RUN       |
| `pnpm verify:full`           | 明确要求完整发布验收时使用；失败保持非零退出         |
| `pnpm verify:baseline`       | 无首次提交的仓库在迭代开始前保存比较基线；不代表通过 |

默认比较 HEAD 与当前文件，包括已暂存/未暂存、新增和删除；重命名检查两端。被 Git 排除但仍影响验证的数据、历史 fixtures 和 pole-audit 本地 JSON/说明也进入比较输入，需要迭代开始时的本地基线；缺基线的新增历史输入会要求扩大验收。无 HEAD 时使用明确保存的基线，缺失则 BLOCKED。本地基线、缓存和运行摘要位于被忽略的 `local-private/verification/`。不要在迭代结束时重建基线以缩小检查范围。

普通文档只检查格式。Vue/CSS 会检查前端相关代码及单测；Standard 加入浏览器测试。服务端加入数据库集成检查。未知路径或共享模块扩大单测范围。Schema、历史数据、依赖变化及认证会话代码要求 Full；根 package.json 经比较仅 scripts 改变时按工具改动处理。安全、发布、仓库政策及许可证路径优先于普通文档分类，运行实时秘密/公开门禁。调度器变动运行自身和既有发布/许可/安全失败行为测试。

目前前端及未知共享影响采用全量单测，Standard 的前端采用默认 Playwright 套件：这是保守扩大范围，不声称具备完整静态依赖分析。现有独立命令仍可直接运行。调度器拆开内嵌构建的测试和 release 命令，每轮只安排一次所需 workspace 或全量构建；不下载新的许可证据，不创建或覆盖视觉基线。

仅格式和 Lint 可缓存，最长 24 小时。摘要覆盖所有 Git 候选文件的内容、路径、工具安装锁及版本、Node/平台、命令参数、环境变量摘要与本地环境文件摘要；不记录环境秘密值。输入不全、过期、变化或失败均重新执行。`--refresh` 强制重验，执行前清除旧成功；失败不保留成功缓存。安全、许可、数据库、浏览器及构建始终实际执行。`CACHED_PASS` 附摘要；不是本轮实际 PASS。

Full 包含类型、Lint、格式、单测、数据库、历史快照、E2E、跨浏览器、3.0 真实浏览器视觉检查、构建、秘密扫描、许可证清单、公开授权门禁、发布包检查及本地制品冒烟。`pnpm verify --dry-run` 列出相同的 Full 计划。

Full 的单测使用显式模式、BO3、身份、积分、账号、全功能及最终角色夹具。为避免混合套件竞争数据库，Full 串行执行测试文件。认证用例通过 `V3_CERTIFIED_TEST_DATABASE_URL` 指向已有隔离还原副本，保留认证源的排序规则和时区。浏览器使用两组 `*_BROWSER_*_URL`，本地制品冒烟使用 `V3_PACKAGED_SMOKE_DATABASE_URL`。各入口校验其所需夹具。备份恢复须另行指定独立目标。

`pnpm test:e2e:v3:visual` 在真实 3.0 业务流程中采集七个页面的桌面及移动截图，检查页面溢出、导航与标题重叠及关键区域可见性。每次保留独立截图证据。`pnpm test:e2e:p4b:visual` 继续用于历史版本和历史基线。

`publication:check` 的非零退出保留为失败门禁（具体 BLOCKER / OWNER_APPROVAL_REQUIRED 查看原门禁输出），不因暂缓许可证问题而假报通过。所有者仍须批准最终公开文件范围及首次 commit/push；任何验证命令均不授予发布权限。
