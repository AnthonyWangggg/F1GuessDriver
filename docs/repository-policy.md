# 仓库文件与公开前检查

## Driver Guess 3.0 公开范围

维护入口为 [maintenance.md](maintenance.md) 与 [部署索引](../deploy/README.md)。`deploy/p4*/`、`deploy/private-access/`、`deploy/public-prep/` 为本地运维和阶段证据，保留原路径及哈希，排除出源码候选及新发布包；通用模板继续保留。历史版本包不因此自动删除或重新认证。

Driver Guess 3.0 的线上发布记录与 GitHub 候选分别审核。每次调整文件范围都需要核对新候选清单、SHA256 和所有者审批。历史版本许可证疑点保持 `UNRESOLVED`，受影响的历史版本不重新引入。新候选仍须执行现有安全、许可证和发布门禁。

`docs/v3/private/` 与 `local-private/` 保留原始阶段报告、真实部署授权、备份证明和验收记录。真实配置、密钥、会话记录、诊断日志和测试输出均留在本地。已进入 Git 索引的资料须从拟提交树中显式移除，最终审核同时检查真实索引与候选 blob。

首次提交必须核对精确 candidate 文件表。无提交历史仍可能存在私有索引产生的 Git 对象；秘密扫描应同时检查对象，不能将整个 `.git` 或私有索引打包上传。发现旧对象中的凭据时保留证据、隔离公开范围，由所有者另行决定轮换及历史清理。

以下说明保留早期阶段的证据与政策背景；阶段状态不作为现生产状态证明。

`reports/source-cache/f1db-v2026.16.0/` 的三个被审计 JSON 文件是固定历史源输入，必须本地保留（不是可随意删除的普通缓存）。不随 Git/HTTP 发布包提交；新维护机需从 data/poles/SOURCES.md 指定的固定发布 ZIP 恢复，核对包 SHA256 和 audit.json 的三份文件 SHA256，随后才能执行严格审计/数据校验。Jolpica 在线响应可能改变，重取不能保证重现旧快照；恢复本项目既有 valid 版本应使用本地加密备份及保留的已认证原始输入。

pnpm 11 的 legacy deploy 会重新解析部署依赖，因此打包后必须遍历实际生产依赖图，核对部署版本与锁文件安装的源工作区版本相同；不一致则失败。打包保护源锁文件与 pnpm 本地状态，生产包清单保存源锁 SHA256 和核验依赖版本。发现 pnpm 自动加入指向原 checkout 的无用自身链接时，仅 unlink 新发布包中的该链接；任何其他外部依赖链接均为 BLOCKER。

用户已确认在 P3.5 后手动修改品牌与 PIT WALL 文案，P4-A 保留这些效果。独立视觉基线保存 `local-archive/visual-baselines/p4-a/`。`pnpm test:e2e:p4a:create` 仅在人工批准建立基线时运行，`pnpm test:e2e:p4a` 为正常只比较的验收命令；原 tests/e2e/*-snapshots 全部保留并核对哈希。首次旧基线命令失败不属于修改断言或替换历史截图。

P4-A 在修改 ignore 前生成本地 `reports/p4-a/file-classification-before.json`。本地开发报告、截图、视觉基线和来源缓存保留原位置，避免断开历史文档及审计路径。不自动移动、删除、提交、推送或改写历史。

| 类型                                               | 推荐提交                         | 发布包                 |
| -------------------------------------------------- | -------------------------------- | ---------------------- |
| apps/packages 源码、测试、锁文件、工具配置、README | 是                               | 应用编译文件及生产依赖 |
| Migration                                          | 是                               | 是                     |
| data 下原创配置、来源、授权                        | 候选，最终范围待所有者批准       | 仅运行配置、许可说明   |
| 混合历史审核与真实数据夹具、audit.json             | 否；保留本地，等待逐文件授权审核 | 否                     |
| reports/pole-audit/legacy-baseline.json            | 纯摘要基线候选                   | 是                     |
| 其余 reports、P0—P4 开发报告、截图/trace/视频      | 否，保留本地                     | 否                     |
| .env、私有密钥、数据库备份                         | 否，限制权限                     | 否                     |
| node_modules、dist、缓存                           | 否                               | 仅受检的运行产物       |

`pnpm security:scan` 检查待提交候选、已跟踪文件及所有可访问提交。结果只包含相对路径和规则名，不输出匹配文本。历史发现秘密时：先撤销/轮换凭据，再另行批准使用 git-filter-repo 清理并协调所有克隆；本脚本不修改历史。

`pnpm release:check` 执行类型检查、构建、秘密扫描、生成新的独立发布目录并实际检查。BLOCKER 非零退出。所有者已批准自有原创源代码 MIT（2026 WONTONANTI），第三方数据及材料不被此 MIT 覆盖。逐文件许可边界和合法重建输入见 DATA-LICENSES.md；未明确授权的混合数据不进入候选。

未跟踪的本地私有文件不属于公开候选。截图和 ZIP trace 默认隔离，不能因源码扫描通过而宣称这些二进制资料已通过隐私审查；公开任何截图前需人工检查。源缓存可按已固定 URL、版本和 SHA256 重取，保留其 CC BY 4.0 来源说明，不能把整个 data/docs 目录忽略。

现有 Playwright 视觉基线留在本机并被排除。新克隆需在受控固定浏览器环境显式建立本地基线并审核，与 CI 单独安全存储的基线对比；正常测试不得使用更新基线参数掩盖失败。

首次公开前使用 `pnpm publication:check` 的私有索引清单审阅实际暂存 blob，用户日常索引不变。清单保存在本地 reports/p4-c1.1/github-candidates.json/.txt，不保存凭据。工具验证已批准的 MIT 标准文本；依赖证据不足仍阻塞，数据范围及最终候选未经所有者确认输出 OWNER_APPROVAL_REQUIRED。`pnpm release` 只证明技术产物检查，不替代公开授权；详见 publication-audit.md。

发布包不包含统计重建工具链或混合历史事实 JSON。维护需合法取得的本地审核输入及锁定工具；维护账户与 HTTP 运行账户分离。发布包保留 Migration、运行配置、来源说明、许可和纯摘要基线，不带来源缓存、日志或开发报告。排除不等于删除，现有资料保留原路径。
