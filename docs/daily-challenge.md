# 每日一题（阶段 B，本地实现）

阶段 A 已独立上线；阶段 B 的数据库迁移、生产环境启用和发布均需另行批准。`DAILY_CHALLENGE_ENABLED` 默认 `false`；关闭时每日接口返回 503，普通游戏不查询每日表。现有生产环境未修改。

## 行为和复用

- 北京时间 00:00 换日，以 PostgreSQL `clock_timestamp()` 为权威时钟。当天首次请求事务创建共同答案；并发实例通过日期主键确定唯一赢家。
- 固定普通难度、8 次，复用现有答案池、认证数据检查、访客 Cookie、车手展示映射和 `compareDrivers`。新每日答案要求 v3；日期保存数据版本和规则版本，恢复时继续使用锁定版本及已保存反馈。
- 同一访客、日期只有一条参赛记录，刷新进入同一记录。未结束对局不返回答案，普通游戏的恢复、揭晓和重开接口不能操作每日记录。
- 结束记录包含猜测次数、成功或失败、完成时间。过期但未完成的记录保留 `playing` 并返回 `expired: true`，不可继续猜测，不伪造失败成绩，也不公开隐藏答案。
- 参与天数以创建每日参赛记录为准，连续参与允许今天尚未进入时延续昨天的记录；不是连续获胜。清除 Cookie 或换设备会产生不同访客身份，首版不提供跨身份成绩合并。
- 页面复用现有搜索、属性表、反馈和样式。提交响应丢失后先查询服务端进度；查询也失败时暂停提交并提示同步。没有重开每日成绩或提前揭晓按钮。

## 数据库增量

仅提议 `0007_daily_challenges.sql`，新增以下五表，不修改既有表、快照或统计：

| 表                  | 一致性约束和用途                                       |
| ------------------- | ------------------------------------------------------ |
| `daily_challenges`  | 日期主键，答案/快照外键，固定规则和 8 次               |
| `daily_entries`     | 访客散列与日期唯一，状态、次数、结果和完成时间检查     |
| `daily_guesses`     | 参赛记录与次数主键、车手唯一，保存当次反馈             |
| `daily_submissions` | 参赛记录与 UUID 幂等键主键，关联已接受猜测并保存原响应 |
| `daily_rate_limits` | 访客主键，跨实例共享每 60 秒 30 次写操作限额           |

猜测事务先锁定归属正确的参赛行；同键同载荷重放原响应，同键不同车手返回 409。锁后重新读取数据库时间，跨午夜等待的请求返回 409，重复车手不扣次数；猜测、次数、结算和幂等回执在同一事务提交。创建参赛记录也在冲突等待后检查日期，跨日整笔回滚。限流独立提交，失败或重放请求同样计数；现有来源校验和进程级基础限流继续适用。

生产迁移前须单独审核 SQL 与摘要、备份目标、应用角色的新表权限和新旧二进制兼容性；先扩展 Schema，再部署默认关闭的 API，获批后启用功能及页面。回退关闭每日入口并恢复固定 web/API 版本，保留五张新增表和新对局，禁止执行删表回滚。旧 API 无每日路由，新页面会显示暂未开放，普通游戏仍可访问。

## API

| 方法与路径                          | 行为                                         |
| ----------------------------------- | -------------------------------------------- |
| `GET /api/daily`                    | 当日日期、刷新时间、固定版本；不返回答案     |
| `POST /api/daily/entry`             | 空请求体；进入或恢复当日自己的记录           |
| `GET /api/daily/entries/:id`        | 仅所有者恢复；结束后才返回答案               |
| `POST /api/daily/entries/:id/guess` | 严格接受 `driverId` 与 UUID `idempotencyKey` |
| `GET /api/daily/statistics`         | 当日参与/胜负/成功次数分布和本人连续参与     |

写请求必须带 `X-F1-Daily-Contract: daily-v1`。客户端不能提交日期、答案或版本。每日 API 与现有 `/api/games` 分离，普通游戏契约不变。

## 隔离验证

使用本机开发数据库只读复制历史数据到新命名的测试 Schema，迁移只在该 Schema 内执行，不修改源库 `public`。冻结阶段 A 源码重新编译作为旧实例，验证 v1/v2/v3 双向恢复、猜测及结算。

```powershell
$env:LOCALIZATION_LEGACY_SOURCE='local-private/localization/closeout-20261016/linux-source-0f149f61aa4e'
pnpm test:localization --daily
pnpm test:localization --daily-e2e
pnpm verify:full --dry-run
pnpm test:localization --daily-full
```

数据库测试覆盖两实例并发创建、幂等重放、重复和最后一次并发、锁等待跨午夜（猜测与创建）、旧版本恢复、限流和归属边界。浏览器测试覆盖实际数据库进度恢复、320/375/1280 页面、终局和响应丢失恢复。Full 的 publication 必须实时执行；阶段 A 批准不能自动批准包含每日功能的新候选，受阻时应如实保留门禁结果。
